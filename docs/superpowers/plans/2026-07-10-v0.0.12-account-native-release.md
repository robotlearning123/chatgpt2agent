# gpt2agent 0.0.12 account-native release implementation plan

> **Status:** execution plan for PR #30 (`release/v0.0.12-account-design`)
>
> **Design:** `docs/superpowers/specs/2026-07-10-account-native-feature-coverage-design.md`
>
> **Release rule:** no merge, tag, or publish unless every applicable gate is green and a non-author approval is present. Voice code is explicitly outside this release.

## Outcome

Release `gpt2agent 0.0.12` from the existing v0.0.12 worktree, branch, and PR with:

- seven bounded account-native read tools;
- two deterministic packaged MCP resources;
- compatible fixes for Apps, generic jobs, and model-aware `thinking_effort`;
- request-local authentication, typed safe errors, bounded account traffic, loopback-only HTTP, and no raw diagnostic persistence;
- explicit annotations for the complete tool registry;
- Python MCP SDK minimum/latest-v1 compatibility and package dry-run coverage on pull requests;
- public no-secret drift radar plus a trusted-local, exact-commit account receipt;
- verified merge, annotated tag, OIDC publication, PyPI canary, and owned-worktree cleanup.

The expected public registry grows from 25 to 32 tools. No Voice route, audio, WebRTC, browser automation, API key, or new runtime dependency is allowed in 0.0.12.

## Execution constraints

- Work only in the dedicated `release/v0.0.12-account-design` worktree and keep PR #30 as the sole v0.0.12 lane.
- Preserve unrelated user changes and avoid action-version upgrades already covered by Dependabot PRs.
- Use repository tooling and add tests before implementation for every behavior change.
- Keep account credentials, cookies, bearer tokens, identities, account content, and raw payloads out of Git, hosted CI, logs, fixtures, and receipts.
- The trusted-local account gate is GET-only and shape-only. It may run only after all offline gates pass for the exact checkout.
- Use the current Python control plane. TypeScript AgentRTC and Voice begin only after 0.0.12 is published and 0.0.13 is synchronized.
- Do not claim cross-process safety for `custom_instructions_set`; document its existing read-modify-write residual risk instead of expanding release scope.

## Commit and verification discipline

Each task follows red-green-refactor:

1. add or amend a narrowly failing test;
2. run the narrow command and preserve the expected failure in the work log;
3. implement the smallest coherent change;
4. rerun the narrow test plus adjacent tests;
5. run `git diff --check` before committing;
6. push only reviewable, internally consistent commits.

The final PR-head verification is run from a clean checkout state. A later source change invalidates package, account, cross-model, and approval evidence tied to the old commit.

## Task 17: Merge, tag, publish, canary, and clean

**Merge gate**

1. Confirm PR head, review decision, mergeability, required checks, and no unresolved blocking thread.
2. Merge using the repository's accepted method without bypassing branch protection.
3. Wait for `main` CI on the exact merge commit.
4. Select the newest immutable candidate-producing attempt from that successful
   main run with at least 72 hours of retention headroom, download its exact
   artifact, and run the trusted-local account gate against those bytes. Do not
   rebuild locally. A failed-only rerun may bind an earlier package attempt; a
   full/package rerun selects the newer artifact and requires a new account gate.

**Release gate**

1. Create annotated tag `v0.0.12` pointing to the verified merge commit and
   include all eight emitted receipt/artifact identity fields.
2. Push the tag and wait for the tag-only OIDC release workflow.
3. Require the workflow to validate the pinned run and artifact live, download
   by numeric artifact ID, reconstruct the account artifact-set digest, and
   publish without invoking a build.
4. Verify GitHub Release and PyPI wheel/sdist filenames and SHA-256 hashes against the exact account-tested artifacts.
5. Install `gpt2agent==0.0.12` from PyPI with no cache in a fresh environment.
6. Run `pip check`, version/CLI, exact 32-tool manifest, packaged resource/Skill, import, and safe local server smoke tests.
7. Run the post-publish canary and save its bounded non-secret result.

**Cleanup gate**

1. Remove only owned build/cache/temp artifacts after classifying reusable generators into Git.
2. Remove the merged v0.0.12 worktree and local branch when safe.
3. Leave the v0.0.13 Voice worktree intact, synchronize it to released main, and begin its separate TDD/PR lane.
4. Audit the parent workspace's 12 known hygiene artifacts; move only confirmed inactive generated residues into a permission-restricted, recoverable local quarantine with a manifest. Never commit them or touch an active lane.

## Definition of done

`0.0.12` is done only when all of the following are simultaneously true:

- implementation, docs, packaged Skill/resources, and version metadata agree;
- offline tests, lint, security, MCP min/latest, package dry-run, and hosted required aggregate are green;
- the successful exact-merge main-CI artifact is immutable, unexpired, and has
  one valid sanitized account receipt binding its full workflow/artifact identity;
- independent final cross-model review has no unresolved blocker;
- non-author approval is present and branch protection is not bypassed;
- annotated tag points to the verified merge commit;
- OIDC publication succeeds without a rebuild and PyPI artifacts match both the
  account handoff and release-workflow evidence;
- fresh no-cache PyPI install and post-publish canary pass;
- owned v0.0.12 artifacts/worktree are cleanly removed;
- v0.0.13 begins from released main with Voice still isolated from the v0.0.12 contract.
